101 was about one piece of work: getting one fix or one feature right. That's the loop. 201 is the layer above: how work is split, what runs in parallel, where a person decides, and how each run makes the next one better. That's the graph.

## Lessons

### 01. [From Loop to Graph](https://clarkhuang.github.io/software-engineering-201/01-from-loop-to-graph/index.md) (available)

A loop makes one piece of work correct. A graph decides which pieces exist and which can run at the same time. Built around how three Software Engineering 101 lessons were made side by side, each with its own review.

**Rule:** Before any job with more than one part, write down the pieces, and which can run at the same time. Then run each piece as its own loop, checked on its own.

### 02. [Find the Real Dependencies](https://clarkhuang.github.io/software-engineering-201/02-find-the-real-dependencies/index.md) (outline only)

“And then” is not a dependency. If nothing crosses between two steps, they don't need to wait for each other.
