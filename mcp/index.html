Site MCP server

A small, read-only MCP server for this site, so an AI agent can see what a reader sees (lessons, transcripts, chapters, captions, video status, watched-progress keys) and report problems the way an outside contributor would.

It is one Python file with no dependencies. It runs on your computer over stdio and reads only this site's public files: lessons.json, search-index.json, the Markdown twins, and the WebVTT captions. It cannot change the site, file issues, or merge anything. draft_issue returns text and a prefilled GitHub link for you, or your own GitHub tools, to file. Machine-readable details are in /.well-known/mcp.json.

Connect it

Claude Code

claude mcp add clarkhuang-site -- uv run https://clarkhuang.github.io/mcp/clarkhuang_site_mcp.py

Cursor, Claude Desktop, and other MCP clients

Add this to ~/.cursor/mcp.json, claude_desktop_config.json, or your client's MCP settings:

{
  "mcpServers": {
    "clarkhuang-site": {
      "command": "uv",
      "args": ["run", "https://clarkhuang.github.io/mcp/clarkhuang_site_mcp.py"]
    }
  }
}

No uv? Download clarkhuang_site_mcp.py and use "command": "python3" with "args": ["/path/to/clarkhuang_site_mcp.py"] (Python 3.9 or later).

To look at staging (the next-revision branch) instead of production, set the environment variable CLARKHUANG_SITE=https://clarkhuang.github.io/staging. To test your own change before you open a pull request, set it to the path of your local clone.

Tools

  • site_info: What the site is, lesson counts, discovery files, how watched progress is keyed, staging vs production. Call it first.
  • list_lessons: Every lesson in AI Tips, Software Engineering 101 and 201: id, status, duration, page and Markdown URLs.
  • get_lesson: One lesson: summary, rule, video, captions and poster URLs, chapters, video version and watched key, and the Markdown twin with the full transcript (captions and AGENTS.md on request).
  • check_lesson_media: HTTP status of a lesson's page, twin, AGENTS.md, video, captions and poster; with no id, every lesson's problems.
  • get_page: Any page as Markdown, for example /, /book/ or /contribute/.
  • search: Keyword search over the site's own search-index.json, with URLs to cite.
  • how_to_contribute: Issue templates, labels, branches, checks, and who merges.
  • draft_issue: A contributor-style issue (steps, expected, actual) with a prefilled GitHub URL and a gh command. It never files anything.

Contribute like an outside contributor

  1. Call site_info, then list_lessons and get_lesson to read what you need.
  2. Call check_lesson_media and read pages with get_page. Compare what you find with what the docs promise.
  3. Found a real problem? Call draft_issue, check the draft for anything private, then file it with the Site or lesson problem form.
  4. To fix it, branch from next-revision, keep each page's index.md, AGENTS.md and llms.txt in sync, run python3 sitegen/check_site.py ., and open a pull request into next-revision with Fixes #N. Only Clark merges to production.

There is also a third-party, remote option: GitMCP. Its full-text fetch is current, but its search can lag behind the site, and it has no lesson or issue tools.
