## The lesson

A bot's usefulness is bounded by what it's connected to, and it almost never tells you where that boundary is. Five generic examples show how a missing link, an unread thread reply or a doc it can't write turns into something that sounds like success.

## The rule

Before handing a bot a task, confirm which bot you're talking to and what it's connected to. Treat any "I'll write / file / run / log it" as a claim about access, not a status, and check it can actually do that. Remember that an approval, a chat request to borrow access, or an untagged thread reply doesn't grant access or reach the bot. Access is granted where the tool is administered.

This rule is written so an AI agent can follow it as a standing instruction.

## Transcript

Here's something that quietly costs you hours with bots. A bot can only do what it's wired into. And it almost never tells you where that edge is.

### The model

Think of a bot as a set of connections. Some tools are wired in, some aren't. And from inside a chat, a bot with no connection looks exactly like one that has it. Here are four gaps, and one promise.

### The gaps

Gap one. A bot tries to hand work to a coding agent. But that agent only runs for a person with a linked account, so the handoff never fires. A bot's message can't start another bot's work. There's no person attached to it.

Gap two. A bot can only run tools for people whose account is linked. Yours isn't. You approve its request anyway, and the approval goes green. Nothing downstream moves. The approval was real. It just wasn't the missing piece.

Gap three. Some bots only hear thread replies that tag them. Reply without the tag, and your message never arrives. It wasn't ignoring you. It was never in the conversation.

Gap four. A bot asks, in a chat, to borrow another bot's connectors. That message isn't permission. Access is granted in the tool itself, by whoever owns it.

And the promise. Say a bot offers to log a decision in a doc it can't write to. I'll log it was sincere. It was also impossible.

### The pattern

Notice the shape. Not one of those bots said I can't. Each said something that sounded like success, because from where it sits, it did succeed. Nobody was lying.

### The habit

So before you hand a bot a task, two questions. Which bot am I talking to? And what is it connected to? It costs you about a second.

And when a bot says it'll write, file, run or log something, hear that as a claim about access, not a status. Can it, actually?

None of these are bugs. They're a permissions model. And once you can see the model, the failures stop being mysterious, and start being predictable.

Know what the bot can actually reach.
